# OVERDRIVE development instructions

This repository develops OVERDRIVE, packaged as a Codex plugin and a Claude Code plugin that share one runtime in `plugins/overdrive/`.

- **Central boundary.** The coordinator conversation in Codex or Claude Code is the only user interface. Deterministic local code owns repositories, durable state, message delivery, lab execution and the worker capability boundary. The coordinator model owns specs, priorities and delivery judgment, and worker agents own implementation (feature agents) and testing (QA agents). Coordinator and worker model choices are independent. Enforce in code only what code can decide exactly; leave judgment to instructions, and do not add lifecycle gates.
- **Names.** Use `overdrive` everywhere: the plugin and skill, the `overdrive` MCP server with unprefixed tools, `overdrive.json`, `.overdrive/`, `refs/overdrive/`, `OverdriveError`. Use the `STATE_DIR` and `CONFIG_FILE` constants from `util.mjs`. Legacy workspaces migrate on first open through `migrateLegacyWorkspace` in `util.mjs` and the schema migration in `state.mjs`. Keep both idempotent, never rebuild or drop `features` or `work_items`, and keep the legacy plugin and server identifiers that worker isolation still disables.
- **MCP protocol.** Persist and return only explicit user instructions, visible agent messages and plans, safe generated summaries, Git facts, lab evidence and lifecycle events. Never store or expose private reasoning, and redact secrets before storage.
- **Evidence integrity.** Only runtime-executed lab runs are evidence. Never record an agent report as a run, and never treat a report as proof when Git state or an executed run can establish the result.
- **Edits.** Use Edit or `apply_patch` for source edits. Match the surrounding style: ESM, small functions, argv arrays, no shell interpolation. Prefer deleting code to adding it.
- **Verification.** After behavioral changes run `node --test tests/*.test.mjs` (a glob, not a directory), `npm run check`, and both plugin validators: `npm run validate:plugin` for Codex and `claude plugin validate plugins/overdrive` for Claude Code. Verify new behavior with temporary probes and remove them. Add a permanent test only for a clear high-risk reason, such as a data migration.
- **Installed plugin.** Codex caches the plugin by version. After changing tools, the skill or the runtime, set the version in `plugins/overdrive/.codex-plugin/plugin.json` to `0.1.0+codex.<UTC yyyyMMddHHmmss>`, reinstall from `overdrive-local`, and test in a fresh task.
- **workspace/.** It is the clean first-run surface. Do not seed it with a repository or generated runtime state.
- **Workbench.** Keep development artifacts worth keeping that must never be pushed (the case-study harness and records, plans, designs, research, reusable probes, generated data) in `.overdrive-workbench/` at the repository root, which `.gitignore` covers; when it holds a README.md, follow it. In a linked worktree, use the main clone's (`git worktree list` prints it first). Subagents return results as text, so save those worth keeping there yourself.
